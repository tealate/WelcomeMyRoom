# Space Editor: 独立した存在範囲・検索エリア・モード切替

対象: Minecraft Java Edition 26.1 / WelcomeMyRoom。ライブの `testpack` と `space_editor_datapack` に直接生成します。

## 使用方法

1. `F3+T` と `/reload` を実行し、`/function space_editor:start` で新しい棒を受け取ります。
2. SpaceLink接続棒でグループを作成し、Proxy存在範囲棒で通常Regionを存在範囲に登録します。RoomID設定は不要です。存在範囲は複数並べたり、重ねたりできます。
3. 必要なら**検索エリア棒**で部屋の対角2点を右クリックします。通常Regionと同じ2点選択で、青い枠と `SearchArea #ID / 検索最適化` ラベルが付きます。移動棒・全体サイズ変更棒・面伸縮棒・削除棒で編集できます。
4. `/function space_editor:projection/enable` の後、**モード切替棒**を右クリックしてプレイへ移り、SpaceLinkに侵入します。もう一度右クリックすると編集へ戻ります。切替結果は既存start/playのチャットで表示されます。

検索エリアは作成時各辺1〜512、拡縮時0.1〜512ブロック。通常Regionは従来の32ブロック上限です。拡縮時のDimension高度制限も維持します。棒を持ち替えると未確定の通常Region/検索エリア選択は混在させず、最初の点からやり直します。大きなエリアの枠には描画距離とカリング範囲を設定していますが、クライアントでの見え方は要確認です。

モード切替はプレイ中もroot tickで検出します。使用イベントを消費してからstart/playを呼び、同じクリックを後段の編集操作へ渡しません。使用イベント間に8tickの空きが必要です。長押し中のイベントは待機時間を延長するため連続切替しません。クールダウンはプレイヤー別で、既存の編集者ロックをそのまま適用します。切替棒はplayで削除されません。

## 存在範囲の変更

同じDimensionのすべてのProxy存在範囲が1つの和集合です。投影した足元がどれかに含まれていれば、経路IDとロード中の表示Entityを維持します。重複しても新しい経路は作りません。minを含みmaxを含まない境界です。全範囲から出ると経路を削除します。存在範囲だけへの再入場では復活せず、SpaceLinkへの再侵入が必要です。

SpaceLinkGroup、経路キー、回転・FlipY・相対座標変換・本人TP・Debug・同期は維持しています。本人TP後の別フレーム選択も従来どおりです。検索エリアは投影の生成条件や存在判定を変更しません。

旧RoomIDは互換用メタデータとして残り、旧set_room APIも使えますが存在検索には影響しません。旧デモはRoomID設定を行わずに動作します。既存ワールドをリセットする必要はありません。ただし以前は別Room扱いだった範囲も同Dimensionなら和集合になるため、従来より長く代理が残る場合があります。

## 採用した検索方式

- **経路ごとの直前命中キャッシュ**: 6境界を半ミリブロック整数へ変換して保存し、1つのmacro内のスコア範囲比較で検査します。経路IDは存在範囲IDに依存しません。
- **手動検索エリアの完全な候補索引**: エリアと座標が重なる同Dimensionの存在範囲を全件登録します。現在点を含む完成済みエリアが1つあれば、その候補だけを検索できます。点を含む存在範囲は必ずそのエリアと重なるため、重複エリアの候補を合算する必要はありません。
- **正しいフォールバック**: 完成済みエリアがない、エリア外、索引再構築中、complete印がない場合はDimension別の全候補へ戻ります。完全な索引の検索結果が空なら、そのまま範囲外と確定できます。
- **変更検出**: root tickでdocument.regionsと検索用snapshotを1回比較し、違えばrevisionを更新してキャッシュと索引を失効させます。Editorの作成・移動・拡縮・削除だけでなく、デモやコンソールからの変更も次のtickで反映します。snapshot比較にはRegion数に比例するNBTコピー・比較コストがあります。
- **処理予算**: 索引構築は8候補/tick。検索は全経路共通で64候補/tick、接点64件以上では48候補/tick。領域検索にも同じ予算を使います。未確定の検索はキューを経路内に保持します。検索済み候補の否定が成立する直方体を記録し、移動先がその中なら途中から続行、外なら再検索します。途中結果を範囲外とみなして経路を消すことはありません。

存在範囲がない場合は空リストの検索で終了し、消えた経路を毎tick再検索しません。SpaceLinkの侵入履歴は保持するので同じ接点から毎tick再生成することもありません。

索引の格納先は `storage space_editor:search`。snapshot/existence/areas/index/buildAreas/buildingが再生成可能な内部状態です。破損が疑われる場合は `/reload` でsnapshotから再構築します。documentや経路の無条件初期化は行いません。検索データをコンソールで直接編集する運用は対象外です。

## 実機での追加確認と限界

青い検索枠・ラベルと2種類の新しい棒の見え方、右クリック長押しと離して再クリックする感触、512ブロック級の枠の見え方はクライアントで未検証です。既存の代理スキン、反転、歩行、名前、削除演出の見た目もサーバーテストだけでは保証しません。

大量のキャッシュミスでは検索が複数tickへ分割され、表示開始・退出時の削除が遅れます。判定待ちの既存表示は最後の確定位置に留まり、新規経路は確定まで表示しません。検索を進めるたびに否定済み領域を飛び越える極端な移動では再検索が増えます。索引の構築総量はエリア数×同Dimensionの存在範囲数なので、意味のない大量・巨大な重複エリアは作らない方が効率的です。静止中は命中キャッシュが効くため検索エリアの追加効果は小さく、索引構築・snapshot・既存Region列挙のコストが増える場合があります。

512件試験は存在検索単体です。64リンク・64存在範囲・2人・Debugの全tick負荷試験と区別してください。既存のSpaceLink/TP走査や描画上限はそのままで、無制限のRegion数や経路数を保証する変更ではありません。
